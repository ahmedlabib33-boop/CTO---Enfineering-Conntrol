======================================================================
80. ML ACCEPTANCE CRITERIA
======================================================================

The Machine Learning implementation is NOT complete unless:

[ ] Genuine trained models exist.
[ ] Models use historical/approved data rather than only hard-coded rules.
[ ] Training data are versioned.
[ ] Feature definitions are controlled.
[ ] Labels are traceable.
[ ] Train/test separation exists.
[ ] Leakage checks exist.
[ ] Cross-validation exists where appropriate.
[ ] Classification metrics exist.
[ ] Regression metrics exist.
[ ] Hyperparameter tuning exists.
[ ] Overfitting is measured.
[ ] Underfitting is measured.
[ ] Confidence is reported.
[ ] Low-confidence predictions can abstain.
[ ] OOD detection exists.
[ ] Feature explanations exist.
[ ] Model versions exist.
[ ] Model registry exists.
[ ] Engineer feedback is stored.
[ ] Approved feedback can become training data.
[ ] Rejected feedback does not become positive training data.
[ ] Actual productivity feeds future learning.
[ ] P6 outcomes feed preparation-quality learning.
[ ] Drift monitoring exists.
[ ] Retraining is controlled.
[ ] New models are tested against the current production model.
[ ] Failed candidate models cannot replace production models.
[ ] Source evidence is never changed by ML.
[ ] Primavera CPM is never replaced by ML.
[ ] Deterministic engineering calculations remain deterministic.
[ ] Complete prediction audit trails exist.

======================================================================
81. FINAL LEARNING OBJECTIVE
======================================================================

Build a system that becomes progressively more intelligent with every
VALIDATED and APPROVED project record.

The objective is:

NOT:

"AI guesses the schedule."

The objective is:

PROJECT EVIDENCE
        ↓
ENGINEERING KNOWLEDGE
        ↓
STRUCTURED HISTORICAL DATA
        ↓
MACHINE LEARNING
        ↓
PROBABILISTIC RECOMMENDATION
        ↓
ENGINEERING VALIDATION
        ↓
PRIMAVERA P6
        ↓
ACTUAL RESULT
        ↓
VERIFIED LEARNING
        ↓
BETTER NEXT RECOMMENDATION.

The system must learn from:

what was planned;
what was recommended;
what the engineer accepted;
what the engineer rejected;
what the engineer modified;
what Primavera produced;
what happened on site;
which crew actually performed the work;
how much quantity was actually achieved;
how long the work actually took;
which equipment was actually used;
which constraints occurred;
which engineering approvals were late;
which procurement packages were late;
which activities became critical;
which constructability problems occurred;
and what final action resolved them.

======================================================================
82. ABSOLUTE ML GOVERNANCE RULE
======================================================================

100% LEARNING means:

100% of VALIDATED + APPROVED + TRAINING-ELIGIBLE evidence shall be capable
of entering the controlled learning system.

It DOES NOT mean:

100% predictive accuracy.

Never falsify accuracy.

Never hide uncertainty.

Never allow ML to rewrite evidence.

Never allow unvalidated records to poison the training dataset.

Never allow test-set leakage.

Never allow rejected engineering recommendations to become approved labels.

Never allow an inferior candidate model to automatically replace a superior
production model.

Never allow ML to replace Primavera CPM.

Never allow ML to replace professional planning and construction judgment.

The final system must therefore be:

EVIDENCE-FIRST
+
DETERMINISTIC WHERE ENGINEERING FORMULAS APPLY
+
PROBABILISTIC WHERE PREDICTION IS APPROPRIATE
+
CONTINUOUSLY LEARNING
+
HUMAN-GOVERNED
+
PRIMAVERA-VERIFIED
+
FULLY TRACEABLE.
